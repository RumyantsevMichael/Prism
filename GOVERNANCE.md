# Governance

Prism has one maintainer, [Michael Rumyantsev](https://github.com/RumyantsevMichael), who decides what Prism does and what lands in it.
The maintainer sets the roadmap, accepts or declines proposals, reviews and merges pull requests, and cuts releases.

## How decisions are made

A feature starts as a proposal issue, and the maintainer accepts it before anyone writes code for it.
An accepted proposal is designed through Prism's own workflow, so its requirements and design are settled before implementation.
A declined proposal is closed with the reason.
How to propose, and what a pull request needs, is in [CONTRIBUTING.md](CONTRIBUTING.md).

## Conduct and security

Everyone in the project follows the [code of conduct](CODE_OF_CONDUCT.md).
Vulnerabilities are reported privately, as [SECURITY.md](SECURITY.md) describes.

## Changes to this document

The maintainer changes this document through a pull request, like any other file.
If the project gains more maintainers, this document will say how they are chosen and how they decide together.
