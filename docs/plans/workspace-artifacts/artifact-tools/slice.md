# Store artifacts through Prism tools

## Changes
- add `src/server/workflow/artifact-paths.mjs`, `dist/server/workflow/artifact-paths.mjs`: `artifactAddress`, which maps a project-relative path to its kind and the path below its configured folder, `malformedArtifactName`, which gives the first component of a path below its configured folder, or of the configured glossary or roadmap file name, that breaks the artifact name form, including a `.` ending and a Windows device name, and `scopeFolder` and `artifactLocation`, which give a scope's folder and an artifact's location in the store, so every later slice maps paths one way (§1-§4, §18).
- change `src/server/workflow/workflow-config.mjs`, `dist/server/workflow/workflow-config.mjs`: `artifactKinds`, the configured artifact kinds by longest path, without `n/a` keys and minus the feature file and user guide folders (§1, §18).
- change `src/server/workflow/record-store.mjs`, `dist/server/workflow/record-store.mjs`: `resolveArtifactFile` and `seenScopes`, which resolve an artifact path in the scopes a checkout sees with the store's resolution, repository name check, and containment and symbolic link checks, and refuse without a store or with an unavailable one, while a stored component folder named by a Windows device name stays seen, and `withArtifactStoreLock`, which holds the store's artifact lock, the file `artifacts.lock` beside the store's `artifacts/` folder (§2, §5, §6, §13, §17, §20, §21).
- change `src/server/workflow/repository-names.mjs`, `dist/server/workflow/repository-names.mjs`: `checkRepositoryName` refuses a `Repository` name that is a Windows device name with `repository_name_invalid` before it registers or writes anything, proposes only a portable name, and lets a registration under such a name accept no checkout and hold no remote (§2, §21).
- change `src/server/workflow/record-store-sync.mjs`, `dist/server/workflow/record-store-sync.mjs`: a sync's apply that replaces a file under `artifacts/` takes the store's artifact lock before the per-file locks it takes, so a sync never lands between an update's version check and its write, and its local commit stages the store under that lock too, so no store commit holds part of an update (§13).
- add `src/server/workflow/store-artifacts.mjs`, `dist/server/workflow/store-artifacts.mjs`: `getArtifact`, `updateArtifact`, and `ARTIFACT_TOOLS`, the read, listing, paging, version, edit, scope, and whole-update checks of the two tools and the `artifact_name_invalid` refusal of malformed names, which listings leave out, the `artifact_name_conflict` refusal of a created or moved path that collides in letter case with a path a seen scope holds before the update or with another write of the update, while a colliding pair already stored stays listed and usable by each path, the `artifact_path_too_long` refusal of a created or moved artifact whose location exceeds 120 characters, while a longer one already stored stays usable, the `component_name_invalid` refusal of a created or moved artifact in a component scope whose name is a Windows device name, while the artifacts of such a folder already stored stay usable, the `invalid_path` refusals that keep every location a regular file, the exact decoding that keeps a byte order mark, and writing by atomic renames while holding the store's artifact lock from the version checks to the last write (§1, §2, §4-§18).
- change `src/server/mcp.mjs`, `dist/server/mcp.mjs`: registers `get_artifact` and `update_artifact` and maps their refusals to JSON-RPC errors with `data.code`, `data.invalidName` for `artifact_name_invalid`, `data.path` for `artifact_name_conflict`, `data.location` and `data.limit` for `artifact_path_too_long`, and `data.component` for `component_name_invalid` (§8, §12, §14, §16, §18, §20, §21).
