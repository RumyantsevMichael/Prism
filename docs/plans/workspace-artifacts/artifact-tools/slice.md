# Store artifacts through Prism tools

## Changes
- add `src/server/workflow/artifact-paths.mjs`, `dist/server/workflow/artifact-paths.mjs`: `artifactAddress`, which maps a project-relative path to its kind and the path below its configured folder, `malformedArtifactName`, which gives the first component of a path below its configured folder, or of the configured glossary or roadmap file name, that breaks the artifact name form, and `scopeFolder` and `artifactLocation`, which give a scope's folder and an artifact's location in the store, so every later slice maps paths one way (§1-§4, §18).
- change `src/server/workflow/workflow-config.mjs`, `dist/server/workflow/workflow-config.mjs`: `artifactKinds`, the configured artifact kinds by longest path, without `n/a` keys and minus the feature file and user guide folders (§1, §18).
- change `src/server/workflow/record-store.mjs`, `dist/server/workflow/record-store.mjs`: `resolveArtifactFile` and `seenScopes`, which resolve an artifact path in the scopes a checkout sees with the store's resolution, repository name check, and containment and symbolic link checks, and refuse without a store or with an unavailable one (§2, §5, §6, §20, §21).
- add `src/server/workflow/store-artifacts.mjs`, `dist/server/workflow/store-artifacts.mjs`: `getArtifact`, `updateArtifact`, and `ARTIFACT_TOOLS`, the read, listing, paging, version, edit, scope, and whole-update checks of the two tools and the `artifact_name_invalid` refusal of malformed names, which listings leave out, writing under the record store's per-file locks and atomic renames (§1, §4-§18).
- change `src/server/mcp.mjs`, `dist/server/mcp.mjs`: registers `get_artifact` and `update_artifact` and maps their refusals to JSON-RPC errors with `data.code`, and `data.invalidName` for `artifact_name_invalid` (§8, §12, §18, §20, §21).
