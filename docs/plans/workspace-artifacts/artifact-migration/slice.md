# Move existing artifacts into the store

## Changes
- add `src/server/workflow/artifact-migration.mjs`, `dist/server/workflow/artifact-migration.mjs`: `migrateArtifacts`, which moves, removes, or keeps each descriptive file of a checkout, keeping each file with a malformed name as `name_invalid` and each file whose new store path would collide in letter case with a path a seen scope holds or with another moved file's path as `name_conflict`, and each file whose location in the repository's scope would exceed 120 characters as `path_too_long`, removes the checkout's roadmap view when it equals the view regenerated from the store's roadmap record and keeps it otherwise as `view_differs` or `no_roadmap_record`, records the moved file's written status, writes one `artifact-migrations/` ledger file, and scans tracked files for moved paths (§26-§29, §31).
- change `src/server/workflow/roadmap.mjs`, `dist/server/workflow/roadmap.mjs`: exports writing the roadmap view generated from the stored roadmap record, which `migrateArtifacts` calls before it compares the checkout's view (§28).
- change `src/server/workflow/record-store.mjs`, `dist/server/workflow/record-store.mjs`: the first access of a checkout in a server process runs `migrateArtifacts` after the record move and keeps its report (§26).
- change `src/server/mcp.mjs`, `dist/server/mcp.mjs`: the migration note lists moved files from checkout path to store location, kept files with both locations, or the checkout path alone for `name_invalid`, with the colliding path for `name_conflict`, the location for `path_too_long`, and the store's view location and the `update_roadmap` remedy for a kept roadmap view, and their reason, and references as `<file>:<line>` (§28, §29).
