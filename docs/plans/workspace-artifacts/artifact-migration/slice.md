# Move existing artifacts into the store

## Changes
- add `src/server/workflow/artifact-migration.mjs`, `dist/server/workflow/artifact-migration.mjs`: `migrateArtifacts`, which takes the checkout's tracked files under its artifact paths from `git ls-files`, lists its untracked files as `untracked` and counts its ignored ones without naming them, moves, removes, or keeps each tracked file, keeping each file with a malformed name as `name_invalid`, each file whose new store path would collide in letter case with a path a seen scope holds or with another moved file's path as `name_conflict`, each file whose location in the repository's scope would exceed 120 characters as `path_too_long`, each file above 1 MiB as `too_large`, and each file that is not UTF-8 text as `not_text`, removes the checkout's roadmap view when it equals the view regenerated from the store's roadmap record and keeps it otherwise as `view_differs` or `no_roadmap_record`, writes the moved files and their status records, including the missing status record of a file the store already holds, then one `artifact-migrations/` ledger file, and only then removes checkout files, and scans tracked files for moved paths with at most 20 line numbers each (§26-§29, §31).

- change `src/server/mcp.mjs`, `dist/server/mcp.mjs`: each tool call names its project root as the checkout whose first access may move, and the migration note lists moved files from checkout path to store location, kept files with both locations, or the checkout path alone for `name_invalid`, `untracked`, and `not_text`, with the size for `too_large`, the colliding path for `name_conflict`, the location for `path_too_long`, and the store's view location and the `update_roadmap` remedy for a kept roadmap view, and their reason, the number of ignored files, and references as `<file>:<line>`, prints every path that holds a control character or line separator as an escaped JSON string, holds at most 32 KiB with a last line that counts what it left out and names the ledger file, and says when a failed pull deferred the move, with the sync's state (§26, §28, §29).
