# Review app UI kit

The review app moves onto one kit: design values in one file, one `prism-*` custom element per kind of control, theme and density choices stored by the review app, shipped fonts, a served catalog, and checks that refuse styling around the kit.
[mockup/mockup.html](mockup/mockup.html) shows the IDE-like look in both themes, built from [mockup/tokens.css](mockup/tokens.css), which holds the proposed values.
The architecture is recorded in [own-ui-kit.md](../../ADRs/review-ui-kit/own-ui-kit.md).

The requirements' design questions are answered here: the IDE-like look is the mockup's (theme-colored chrome for the top bar, sidebar, and status bar, hairline borders instead of shadows, 24px controls and 22px rows at 13px text, small radii, and shadows only on menus, dialogs, and tooltips); the review app stores the theme and density for the user (§15), because browser storage is lost when the port changes; and the palette keeps its hues while these shades darken or lighten for contrast: light `ink-muted` `#6d687e`→`#5f5a71`, `danger` `#c6384f`→`#b42f48`, `warning` `#b26f00`→`#8a5600`, `success` `#15845f`→`#127556`, `info` `#2a78d6`→`#2264b8`, the syntax comment, number, literal, meta, and variable colors, and dark `ink-muted` `#a09bad`→`#a29dae` and `info` `#3987e5`→`#6aa8f0`, with a new interactive boundary color `line-control` in both themes.

In this contract `<base>` is a project's review URL without its trailing slash, `kit/` and `styles/` are folders of `src/server/review/public/`, and the build copies both to `dist/server/review/public/` as it copies the other browser assets.

## Contract

### Files and routes

1. The review server serves every file under `kit/` at `<base>/kit/<path>` and every `styles/<name>.css` at `<base>/styles/<name>.css`, typed `text/css; charset=utf-8`, `text/javascript; charset=utf-8`, `text/html; charset=utf-8`, `text/plain; charset=utf-8`, or `font/woff2` by the extensions `.css`, `.js`, `.html`, `.txt`, and `.woff2`, with the same security headers as the review page.
2. A path under `kit/` or `styles/` that does not exist, leaves its folder, or has any other extension answers 404.
3. `<base>/kit/catalog` serves the catalog page.
4. The review page's head loads `kit/boot.js` as a classic script, then `kit/tokens.css`, `kit/kit.css`, and the area stylesheets in that order, and the page loads `kit/kit.js` as a module before `review.js`.

### Design values

5. `kit/tokens.css` declares every custom property that [mockup/tokens.css](mockup/tokens.css) declares, under the same selectors, and no other file of the review app declares a raw design value.
6. A theme is one rule that gives a value to every `--prism-color-*` and `--prism-shadow-*` property, the semantic tokens, under `[data-theme="<name>"]`: the shipped themes `light` and `dark` are two such rules that declare the same set of names, the light rule's selector list is exactly `:root, [data-theme="light"]` so light is the default, no other rule of `kit/tokens.css` declares a semantic token, compact sizes sit on `:root`, and comfortable sizes on `[data-density="comfortable"]`, so any element that carries one of these attributes renders its subtree in that theme or density.
7. Every color the review page and the catalog paint, including code highlighting, diff lines, status tones, the brand mark's tint, and the diagram sheet, comes from a semantic token, and shadow-DOM controls read the same tokens through inheritance, so supplying another value set restyles every surface; custom themes beyond light and dark are not built now.
8. Inside `@media (prefers-reduced-motion: reduce)` every `--prism-duration-*` property is `0ms`, and every transition and animation of the review page and the catalog takes its duration from a `--prism-duration-*` property, so all computed transition and animation durations are zero there.
9. In each theme, where a name below stands for `--prism-color-<name>` and each such value is a six-digit hex color: `ink`, `ink-muted`, and `accent-text` reach 4.5:1 on `bg`, `chrome`, `surface`, `sunken`, `raised`, `hover`, and `selected`; `line-control` and `focus` reach 3:1 on those seven; `danger`, `warning`, `success`, and `info` reach 4.5:1 on `surface`, `raised`, `sunken`, and their own `-soft` color; `ink` reaches 4.5:1 on every `-soft` color; `accent-text` reaches 4.5:1 on `accent-soft`; `on-accent` reaches 4.5:1 on `accent`; every `syntax-*` color reaches 4.5:1 on `surface` and `sunken`, and `diff-added` and `diff-removed` reach 4.5:1 on `surface` and on their own `-soft` color; the guarantee covers the shipped themes only.

### Fonts

10. `kit/fonts/` holds Inter and JetBrains Mono as variable WOFF2 files with their SIL Open Font License texts `OFL-Inter.txt` and `OFL-JetBrains-Mono.txt`, and `kit/tokens.css` declares them as the font families `Prism UI` and `Prism Code` with sources relative to itself.
11. `--prism-font-ui` starts with `"Prism UI"` and `--prism-font-code` with `"Prism Code"`, and the review page renders body text in Prism UI and `code`, `pre`, and `kbd` text in Prism Code, both loaded from the review app while every other host is unreachable.

### Preferences

12. `GET <base>/api/preferences` answers 200 with `{"theme":"system"|"light"|"dark","density":"compact"|"comfortable"}`, giving `system` and `compact` for a value that is missing, unreadable, or invalid in storage.
13. `PUT <base>/api/preferences` with a JSON object holding `theme`, `density`, or both stores those values, keeps the stored value of the key it leaves out, and answers 200 with the full stored preferences.
14. A PUT whose body is not a JSON object, holds neither key, holds another key, or gives another value answers 400 with `{"code":"invalid_preference","message":<text>}` and stores nothing, and a PUT without a JSON content type or with an `Origin` of another host answers 403.
15. The review app stores the preferences in `review-preferences.json` in the review app folder, which is `PRISM_REVIEW_APP_DIR` when set and the platform's Prism state folder otherwise, so every project, port, and private session server of one user reads the same choice, including after a restart on another port.
16. The page sets `data-theme-choice` (`system`, `light`, or `dark`), `data-theme` (`light` or `dark`), and `data-density` (`compact` or `comfortable`) on `<html>`: before the first paint from the last choice this browser saw at this origin, then from the server's answer, which wins, and it keeps the browser's choice or the defaults when the server cannot be reached.
17. While the choice is `system`, `data-theme` follows the operating system's color scheme and changes when that setting changes, without a reload, and while the choice is `light` or `dark` it ignores the operating system.
18. `<meta name="theme-color">` carries the current value of `--prism-color-chrome`.

### Theme, contrast, and density on every screen

19. Every visible element of the review page and the catalog that paints a non-transparent background color paints a different color in the dark theme than in the light theme, except SVG content and the sheet behind a rendered PlantUML diagram, which keeps `--prism-color-diagram-paper` in both themes.
20. Every visible text of the review page and the catalog reaches 4.5:1 against the background behind it, or 3:1 at 24px and above or at 18.66px bold and above, in both themes and both densities, and text of a disabled control is exempt.
21. Every visible enabled control that draws a boundary, a border or a fill that differs from what surrounds it, draws at least one border side or its fill at 3:1 against what surrounds it, in both themes.
22. Every focusable kit control shows a 2px solid outline in `--prism-color-focus` with a 1px offset when it takes focus from the keyboard, in both themes.
23. Compact is the default density, and comfortable raises `--prism-control-height` from 24px to 30px, `--prism-row-height` from 22px to 28px, `--prism-font-size-md` from 13px to 14px, and every `--prism-space-*` step, while every kit control takes its height from one of those two properties.

### Appearance menu

24. The status bar ends with a kit button named `Appearance` that opens a kit menu holding a `Theme` group of radio items `System`, `Light`, and `Dark`, a `Density` group of radio items `Compact` and `Comfortable`, and an item `Component catalog`, with the current choices checked.
25. Choosing a theme or density item applies it at once, stores it through `PUT <base>/api/preferences`, and closes the menu, and choosing `Component catalog` opens `<base>/kit/catalog` in a new tab.

### Kit elements

26. `kit/kit.js` is an ES module that imports without a DOM and exports `KIT_ELEMENTS`, an array of element classes that each carry a static `tag` and a static `catalog` of `{ purpose, options: [{ name, values, default, description }], states: [<state name>], keyboard: [<sentence>] }`, and `defineKit()`, which defines each element once and does nothing when called again; loading it in a page defines every element.
27. `KIT_ELEMENTS` holds at least these tags, the first ten rendering in shadow DOM and the rest in light DOM: `prism-button`, `prism-icon`, `prism-chip`, `prism-badge`, `prism-tab`, `prism-menu-item`, `prism-tooltip`, `prism-stat`, `prism-meter`, `prism-spinner`, `prism-tabs`, `prism-menu`, `prism-menu-group`, `prism-field`, `prism-option`, `prism-choice`, `prism-choice-option`, `prism-panel`, `prism-tree`, `prism-tree-item`, `prism-listbox`, `prism-list-item`, `prism-dialog`, `prism-disclosure`, `prism-empty-state`, `prism-banner`, `prism-toast`, `prism-doc`, and `prism-code`.
28. `prism-button` takes `variant` (`default`, `primary`, `ghost`, or `danger`), `disabled`, `pressed` (exposed as `aria-pressed`), and `label` (its accessible name when it shows only an icon), renders one native button around its content, lets a click of an enabled button reach listeners on the element, sends no click while disabled, and activates on Enter and Space.
29. `prism-icon` takes `name`, one of at least `search`, `close`, `chevron-right`, `chevron-down`, `store`, `sync`, `maximize`, `restore`, `external`, `check`, `warning`, `info`, and `more`, draws it in the current text color, and stays hidden from assistive technology unless `label` names it.
30. `prism-chip` takes `tone` (`neutral`, `accent`, `danger`, `warning`, `success`, or `info`), `href`, which makes it a link, and `interactive`, which makes it a button, and shows children with `slot="meta"` as quieter secondary text; a chip without either is static text.
31. `prism-badge` takes `tone` as `prism-chip` does and `variant` (`count` or `status`), and is static text.
32. `prism-tabs` has the role tablist named by `label`, and each `prism-tab` has the role tab and takes `value`, `selected` (exposed as `aria-selected`), `closable`, which adds a close button named `Close <tab text>`, `preview`, which sets its text in italics, and `dimmed`.
33. In `prism-tabs` only one tab is in the Tab order, ArrowLeft and ArrowRight move focus with wrapping, Home and End move to the first and last tab, Enter, Space, and a click select a tab and send `prism-select` with `detail.value` from the tabs element, Delete on a closable tab or its close button sends `prism-close` with `detail.value`, and tabs that do not fit scroll inside the strip.
34. `prism-menu` takes `for`, the id of the kit button that opens it, and `open`, sets `aria-haspopup="menu"` and `aria-expanded` on that button, and holds `prism-menu-group` elements named by `label` and `prism-menu-item` elements that take `value`, `type` (`action`, `radio`, or `checkbox`), `checked`, and `disabled`, with the roles menu, menuitem, menuitemradio, and menuitemcheckbox and `aria-checked`.
35. Enter, Space, or ArrowDown on a menu's button opens the menu with focus on its first enabled item and ArrowUp with focus on its last, ArrowUp, ArrowDown, Home, and End move focus, Enter, Space, or a click on an item send `prism-select` with `detail.value` from the menu, close it, and return focus to its button, Escape closes it and returns focus, Tab or a click outside closes it, and the open menu stays inside the window, opening above its button when there is no room below.
36. The kit adds one `prism-tooltip` to the document, which shows the full text of a kit element that has a `tip` attribute or whose text is shortened, as an element with the role tooltip that the element names through `aria-describedby`, after `--prism-tooltip-delay` of hover and at once when the element takes keyboard focus, and hides it on pointer leave, blur, or Escape, while kit elements never render a native `title` tooltip.
37. A kit element that shows one line of text ends text that does not fit with an ellipsis, carries the attribute `shortened` while it does, and joins the Tab order while shortened when it is not focusable already, and a kit element that holds more items than fit scrolls them inside itself or wraps them, so no kit element grows past its container.
38. `prism-field` takes `type` (`text`, `search`, `textarea`, or `select`), `label`, which it shows and associates with the control, `hint`, `name`, `value`, `placeholder`, `required`, `disabled`, `invalid`, and `error`, which it shows and links through `aria-invalid` and `aria-describedby`, creates one native control in its light DOM, reads and writes that control through its `value` property, lets the control's `input` and `change` events bubble, and turns `prism-option` children with `value` and `selected` into the options of a select.
39. `prism-choice` is a radio group named by `label` that takes `name` and `value` and holds `prism-choice-option` elements that take `value`, `tone`, and `disabled` and show their content with children of `slot="detail"` as a description, creating one native radio input per option, so arrow keys move the choice and a `change` event bubbles after the `value` property updates.
40. `prism-panel` takes `heading`, `level` (2 by default), `eyebrow`, `source`, `variant` (`card`, `plain`, or `inset`), and `maximizable`, which adds a button named `Maximize` or `Restore` that toggles the `maximized` attribute and sends `prism-maximize` with `detail.maximized`, renders its heading as a heading element of that level, places children with `slot="tools"` in its header and `slot="footer"` after its body, and keeps every other child in its body.
41. `prism-tree` has the role tree named by `label`, and each `prism-tree-item` has the role treeitem with `aria-level`, takes `label`, `value`, `expanded`, and `selected`, shows children with `slot="end"` after its label, holds its child items in a group, and exposes `aria-expanded` when it has child items.
42. In `prism-tree` only one item is in the Tab order, ArrowDown and ArrowUp move to the next and previous visible item, ArrowRight expands a collapsed item or moves to its first child, ArrowLeft collapses an expanded item or moves to its parent, Home and End move to the first and last visible item, and Enter or a click selects an item and sends `prism-select` with `detail.value` from the tree.
43. `prism-listbox` has the role listbox named by `label` and holds `prism-list-item` options that take `value` and `selected`; with `for` naming a kit field, focus stays in the field, ArrowDown and ArrowUp move the active option through `aria-activedescendant`, and Enter sends `prism-select` with `detail.value`, and without `for` the listbox itself takes focus and the same keys apply.
44. `prism-dialog` takes `heading`, `open`, and `size` (`sm`, `md`, or `lg`), has the role dialog with `aria-modal="true"` named by its heading, opens with `show()` as a modal with focus moved inside it and kept inside while open, closes with `close()`, Escape, or its close button named `Close`, sends `prism-close`, and returns focus to the element that had it before it opened.
45. `prism-disclosure` takes `summary` and `open`, shows a toggle button with `aria-expanded` that Enter, Space, and a click toggle, and sends `toggle` when it opens or closes.
46. `prism-empty-state` takes `heading` and shows its children below it, and `prism-banner` takes `tone` (`info`, `warning`, `danger`, or `success`), `heading`, and `dismissible`, which adds a button named `Dismiss` that sends `prism-dismiss`, with the role alert for `danger` and status otherwise.
47. `prism-toast` is one live region with the role status and `aria-live="polite"` whose `show(message, { tone })` replaces any shown message and hides it after a time taken from the design values.
48. `prism-stat` takes `label`, `value`, `hint`, and `tone`, `prism-meter` takes `value` from 0 to 100 and `label` and has the role progressbar with `aria-valuenow`, or no `aria-valuenow` while it has no value, and `prism-spinner` takes `label`, has the role status, and stands still under reduced motion.
49. `prism-doc` holds rendered Markdown in light DOM and styles its headings, paragraphs, lists, links, tables, quotes, inline code, code blocks, and images from the design values, and `prism-code` holds a code block in light DOM, takes `language`, `numbers`, and `start`, shows line numbers from `start` when `numbers` is set, and colors `tok-<name>` spans with `--prism-color-syntax-<name>`.

### Catalog

50. The catalog renders one `<section data-catalog-entry="<tag>">` per element of `KIT_ELEMENTS`, which holds the tag in its heading, `[data-doc="purpose"]`, `[data-doc="options"]`, `[data-doc="states"]`, and `[data-doc="keyboard"]` filled from the element's `catalog`, one `[data-specimen="<state>"]` with a live instance per listed state, and specimens `long-text` and `unbroken-name`, plus `many-items` for an element that holds items.
51. The catalog's first entry, `<section data-catalog-entry="design-values">`, lists every semantic token by name with its value and a swatch in each shipped theme, and every other design value by name and value, read from the stylesheet the page loaded, so the token names are a documented, stable contract.
52. The catalog's toolbar holds kit controls that set its theme (`System`, `Light`, or `Dark`), density, and width (`Narrow` at 320px or `Wide`) for the catalog alone, the query `?theme=light|dark&density=compact|comfortable&width=narrow|wide` sets them on load, and without them the catalog follows the stored preferences.

### Layout check

53. `scripts/review-demo/layout-audit.mjs` exports `checkCatalog({ url, viewports, themes })`, which opens a catalog URL with an installed Playwright at each named viewport (`phone`, `tablet`, `laptop`, `short`, `wide`, or `ultra`) and theme (`light` or `dark`), emulating the theme as the operating system's color scheme and setting it in the `theme` query and resolves to one `{ entry, viewport, width, theme, problem }` for each catalog entry that escapes its container, cuts off a control, or scrolls the page horizontally, where `entry` is the entry's `data-catalog-entry` and `width` the viewport width in pixels.
54. `scripts/review-demo/layout-check.mjs` also checks the catalog at each of its viewports and themes, prints each catalog problem as `catalog <entry>: <problem> at <viewport> (<width>px), <theme>`, and fails when there is one.

### Guard

55. `scripts/review-kit/kit-guard.mjs` exports `checkKitUsage({ root, files })`, which reads each file path relative to `root` and resolves to findings `{ file, line, rule, value }` sorted by file and line, and as a command, `node scripts/review-kit/kit-guard.mjs [root]` checks every file under `src/server/review/public/`, prints `<file>:<line>: <rule> <value>` per finding, and exits 1 when it finds one.
56. The rule `raw-value` reports, outside comments and in any file except `kit/tokens.css`, a color literal in CSS, JavaScript, or HTML (a hex color of 3, 4, 6, or 8 digits not preceded by `&` or a word character, an `rgb`, `rgba`, `hsl`, `hsla`, `hwb`, `lab`, `lch`, `oklab`, `oklch`, or `color()` function, or in CSS a named color other than `transparent` and `currentColor`), and in CSS, or through `.style` in JavaScript, any literal in `font-size`, `font`, `margin*`, `padding*`, `gap`, `row-gap`, `column-gap`, `border-radius*`, `box-shadow`, `text-shadow`, and `z-index` other than `0`, `none`, `auto`, `inherit`, `initial`, `unset`, and a unitless factor inside `calc()`, and any time in `transition*` and `animation*`, also as a `var()` fallback, with the literal as `value`.
57. The rule `control-style` reports, in a CSS file outside `kit/`, a selector that names one of the elements `button`, `input`, `select`, `textarea`, `dialog`, `details`, `summary`, `option`, `progress`, and `meter`, a `role` attribute with a control role, a `prism-` element or its `::part()`, or a class that ends in `-chip`, `-badge`, `-pill`, `-tag`, `-button`, `-btn`, `-tab`, `-tabs`, `-menu`, `-tooltip`, `-dialog`, `-modal`, `-tree`, `-toast`, `-banner`, `-card`, `-panel`, `-field`, or `-empty` and does not start with `tok-`, with the selector as `value`.
58. The rule `native-control` reports, in a JavaScript or HTML file outside `kit/`, markup or a `createElement` call for one of those elements, a `role` attribute with a control role, or a `title` attribute, with the matched text as `value`, where the control roles are button, checkbox, combobox, dialog, listbox, menu, menuitem, menuitemcheckbox, menuitemradio, option, progressbar, radio, radiogroup, slider, switch, tab, tablist, tooltip, tree, and treeitem.

### Screens on the kit

59. `#artifact` carries `aria-busy="true"` while a view loads and `aria-busy="false"` once the view has rendered.
60. Jump to opens on Ctrl+K or Meta+K as a kit dialog with focus in its search field and its matches in a kit listbox driven from that field, and Escape closes it and returns focus, while the open artifacts are a kit tablist, the sidebar's places, initiatives, and library are kit trees, and the project switcher is a kit menu.
61. Each screen keeps what it shows and how review, gate answers, and navigation behave, and only its look changes.
62. Each migration slice leaves the files its frozen guard test names without a finding, and when every slice is done `checkKitUsage` finds nothing under `src/server/review/public/`, `review.css` is gone, and `<base>/review.css` answers 404.

## Assumptions

- Probed: the page's policy `style-src 'self'` refuses a `<style>` element in a shadow root but applies an adopted constructed stylesheet and a shadow `<link rel="stylesheet">` from the same origin (a scratch page served with the review server's policy header and opened in Chromium through Playwright 1.63; observed the computed colors of the adopted and linked sheets and a refusal message for the style element).
- Probed: a WOFF2 font from the same origin loads under the page's policy (`document.fonts` reported the face `loaded` in the same probe).
- Probed: browser storage is separate per port (a value stored on one port read as missing on a second port of 127.0.0.1), which is why the review app stores the preferences.
- Probed: Playwright's `emulateMedia({ colorScheme })` fires a `change` event on `matchMedia("(prefers-color-scheme: dark)")`, and a custom property overridden in `@media (prefers-reduced-motion: reduce)` computes as `0ms` under `emulateMedia({ reducedMotion: "reduce" })`.
- Probed: Inter 5.3.0 and JetBrains Mono 5.3.0 variable WOFF2 files and their OFL texts are available from the npm packages `@fontsource-variable/inter` and `@fontsource-variable/jetbrains-mono` (`npm pack`; latin subsets of 48 KB and 40 KB).
- Probed: the proposed values in [mockup/tokens.css](mockup/tokens.css) pass every pair of §9 in both themes, including the diff pairs (the frozen tokens test run against a temporary copy of the file: every contrast and theme-set test passed).
- Probed: Playwright 1.63 and its Chromium are installed globally in the environment where verification runs (`npm root -g` lists `playwright`; `chromium.launch()` succeeds).
- Unprobed: Playwright on other machines and in CI, which installs none; a browser acceptance test skips with `Playwright is not installed; run npm install -g playwright and npx playwright install chromium`, never passes without running.
- Unprobed: Firefox and Safari behavior of adopted stylesheets and shadow accessible names; the kit falls back to a shadow `<link rel="stylesheet">` where `adoptedStyleSheets` is missing, and every icon-only control carries `label`, which becomes its accessible name.
