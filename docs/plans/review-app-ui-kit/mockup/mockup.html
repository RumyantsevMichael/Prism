Context

The existing strategy owns timeout retries, and a total deadline bounds every retry sequence, as Bound retries by a total deadline decides. The flow is drawn in the Retry until the total deadline diagram, open beside this page.

Connection retries stay out of scope until their own slice.

Contract4 clauses · 7 frozen tests · 1 unchecked

  1. 1

    A request that times out is retried while time remains on its total deadline.

  2. 2

    No attempt starts after the total deadline has elapsed.

  3. 3

    Each retry waits a backoff that doubles from 200 ms and never exceeds 2 s.

  4. 4

    A request that runs out of time fails with DeadlineExceeded and reports the time it spent.

    No test checks this clause

Interface

// Bounded by the total deadline, never by an attempt count.
export class RequestRetryStrategy {
  shouldRetry(error: Error, deadline: TotalDeadline): boolean {
    return error.name === "TimeoutError" && deadline.remaining() > 0;
  }
}
