Serves: Reliable planning and resumable work in Prism's spec-driven engineering workflow.

## Initiative index

### Now

- **Shared record store** (`shared-record-store`): Let every checkout and machine of a project share one set of Prism records through an ordinary Git repository, without losing bytes or colliding on unrelated changes.
- **Single review app** (`single-review-app`): Run one review app per user that every agent session and project shares, with a project switcher that shows which project waits on the user.
- **Repository intelligence** (`repository-intelligence`): Give workflow agents deterministic repository evidence: providers, context planning, session capacity, structural analysis, and duplication gates.
- **Launched sessions from the review app** (`launched-sessions`): Let the person start, watch, stop, and continue an initiative's orchestration as a headless Claude Code or Codex session on their own machine, resumed by Prism when they answer its gates.

### Next

- **Agent execution evidence and continuity** (`agent-execution-evidence`): Report observed context ranges, keep pause checkpoints current and recoverable, and assess diagram readability.
- **Workspace artifacts in the store** (`workspace-artifacts`): Keep a workspace's requirements, ADRs and plans in its shared store, reviewed in Prism and changed in status only at gates, while executable artifacts stay with the code.
- **Show a whole workspace in the review app** (`workspace-view`): Make the workspace, one record store, the unit the review app opens: list workspaces only, combine every scope's artifacts for people and agents, add a workspace from its store URL alone, and show code-repository content from Prism-kept clones. Requires `workspace-artifacts`.
- **Nested work items** (`nested-work-items`): Replace initiatives with one nested work item, so any node of the work tree is a work item and a leaf done in one session stays a slice, and migrate existing records, terms, tools and skills to it while a top work item pins each reference repository it reads to a commit that its children inherit. Requires `workspace-artifacts`.
- **Artifact formats and migration** (`artifact-formats`): Give every normative artifact type one format with a conforming example, report artifacts that break it, and migrate them behind a gate without losing or inventing content.
- **Questions about records and code** (`record-search`): Answer with records rather than passages, find similar and governing records for an intent, and read the recorded links between records and code in both directions. Requires `index-preparation`.
- **Search of reference repositories and libraries** (`reference-search`): Let a separate search_references tool answer from reference repositories, libraries, and peer workspaces' records at the commit or version a work item pins, without mixing them into the project's own results. Requires `index-preparation`, `record-search`, `reference-repositories`.
- **Reference repositories in the workspace** (`reference-repositories`): Let a workspace list repositories it reads but does not work in, with their components and default version, list each component's libraries, pin and cite the outside code each work item builds on, and show both on a workspace page and a work item settings page. Requires `workspace-artifacts`, `workspace-view`, `nested-work-items`.
- **Work that spans several repositories** (`cross-repo-work`): Let one piece of work change several repositories of a workspace while each repository keeps its own change map, review and pull request: a contract that pins the commit it assumes in each repository, slices in one repository that depend on slices in another, a merge order in which every intermediate state still works, and a dependency on an unreachable repository counted as blocked rather than failed. Proven on a public provider and consumer pair against a one-shot. Requires `workspace-artifacts`, `nested-work-items`.

### Later

- **Emerging work items** (`emerging-work-items`): Let an agreed idea sit on the roadmap as an emerging work item before requirements exist, gather input over many sessions, and merge, split or stay separate on a person's confirmation; show one-slice work items with a roadmap filter, and scale coordination (gates, sessions, splits) with a work item's size, never its artifacts. Requires `nested-work-items`.
- **Map from intent to code** (`intent-map`): Record the provenance events Prism witnesses (input to work item, work item to the records it changed and its commits) and compute links between code and requirements, ADRs, tests and glossary terms on demand from coverage, history and similarity, weighting brownfield sources: Approved records first, then Draft records derived from tests, then old documents as input, then code with no record as a gap. Requires `record-search`.
- **Intake of any input** (`intake`): Capture any input (bug report, idea, request, notes) from any channel into an inbox without judgement, then process it through an intake session and a route gate that decides whether it enriches existing work, becomes a new work item, or is dropped, with orchestrate as the only entry point a person uses; app uploads and a server with connectors come later. Requires `emerging-work-items`.
- **Team collaboration on shared work** (`team-collaboration`): Let several people work on the same initiatives through the shared store: the review app shows live who works on which slice, gate approvals record who approved and when, people are notified when a dependency lands or a contract defect blocks their slice, and nobody sees records of a repository they cannot read. Requires `cross-repo-work`.
- **Platform map from declared interfaces** (`platform-map`): Show how the services of a workspace connect, built from the interfaces they declare (OpenAPI, protocol buffers, event schemas, infrastructure outputs), with inferred links shown only as hints, and read an existing service catalog when the workspace has one. Requires `reference-repositories`.
- **Let a separate package extend the Prism app** (`app-extension-points`): Let a separately installed package add places, pages, actions and server routes to the Prism app, reading and writing records only through the same store interface the app uses, so team features can ship as their own package without forking the app or living in the open repository. Without such a package the open app works exactly as it does today.
- **Deploy the Prism app for a whole team** (`team-server`): Run the Prism app once for a company, self-hosted, where people sign in with company single sign-on and see every workspace they may read (work in flight, roadmap, documents and history) without a checkout, the plugin or git. The server reaches the git host with its own app identity, writes the store on behalf of signed-in people, records the real person on every commit it makes, and decides who may see which workspace from single sign-on groups. It is a read-mostly hosted mode: it never runs tests, launches harness sessions or reads local paths, and its view of running work is as fresh as the last store sync, which it shows. Requires `workspace-view`, `app-extension-points`.
- **Let product owners comment and submit requests** (`stakeholder-input`): Let people who don't write code, such as product owners, comment on requirements, decisions and work items in the team server and submit new requests into intake. Each comment and request is stored in the shared store under its author's name, reaches the agents at the next session or gate that reads that work, and shows its author what became of it. Approving gates as a non-developer comes after comments and requests, with rules per gate for who may approve. Requires `team-server`, `intake`.
- **Connect Jira, GitLab and Confluence** (`connectors`): Bring requests into intake from issue trackers such as Jira and GitLab issues, and publish accepted requirements and decisions to wikis such as Confluence, while the store stays the source of truth: a published page is marked as generated and links back to Prism, and an edit made on the other side comes back as a comment, never as an overwrite. Requires `team-server`, `intake`.

- **Review loop decisions from the findings** (`review-loop-decisions`): Let the user accept a slice whose remaining review findings are all low with tracked follow-ups, and ask the review loop decision with a findings summary, only options Prism can carry out, and a recommendation by a stated rule. Shipped 2026-11-11.
- **Index preparation that finishes** (`index-preparation`): Make every native index build finish while it makes progress, publish structure before embeddings, keep a stopped build's work, keep scoped calls fast, and rank searches across indexes as well as inside one. Shipped 2026-11-12.
- **Initiative settings from the review app** (`initiative-settings-actions`): Let the person change an initiative's orchestration settings from the review app through a generic, revision-checked action mechanism that only the person's page can write and that later actions reuse unchanged. Shipped 2026-11-08.
- **Components in one repository** (`components`): Let a repository declare components with their own test commands and dependencies, keep each leaf slice inside one component, run dependents' tests when a spanning scope finishes, and prepare the native index per component so a large monorepo fits its limits. Shipped 2026-11-07.
- **Repository names in a shared store** (`repository-names`): Name each repository that shares a record store by a committed name the store registers with its remote, and let each machine know where its checkouts of each repository are. Shipped 2026-11-03.
- **Review app UI kit** (`review-app-ui-kit`): Give the review app one set of design values, one shared component per kind of control, theme and density choices, and a served catalog with checks, so every screen stays consistent as it moves toward an IDE-like tool. Shipped 2026-11-09.
